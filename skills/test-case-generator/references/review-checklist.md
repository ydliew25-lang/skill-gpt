# 测试用例生成质量检查清单

## 矩阵与编号
- [ ] 商品/模块数量、场景维度、问答/边界分支与用户指定一致。
- [ ] 矩阵理论数量计算准确；实际输出行数匹配。
- [ ] 编号全局连续、唯一，且沿用用户既有编号。
- [ ] 组合不存在重复、遗漏、概念混淆。

## 单行可执行性
- [ ] 六列均有内容，每条可以独立执行。
- [ ] 前置条件不是“同上/同TC-xxx”，物料、动作起始位、模块状态明确。
- [ ] 每条测试步骤有清晰触发、行动、观测、结束点。
- [ ] 有超时则写明从什么事件开始计时。
- [ ] 多轮问答明确追问在等待窗口内、计时重新起算。
- [ ] 一轮结束及下一轮状态继承正确。

## 技术真实性
- [ ] 已确认与拟实现、待确认能力明确区分。
- [ ] 未将传感器观察误写为更高层语义识别。
- [ ] 未假设动作/语音/检测支持尚未确认的并发。
- [ ] 未凭空增加硬件、成功率阈值、超时数字、异常恢复动作。
- [ ] 与设备动作、商品名称、原料容器、语音知识库匹配。

## 预期与安全
- [ ] 每个预期效果可由结果、状态、时间、录像或日志验收。
- [ ] 失败可定位到具体环节（而非只写整轮失败）。
- [ ] 非标准拿取不要求强拉夹持物或在机械臂运动时碰撞试验。
- [ ] Blocked/待确认的场景有可说明的条件，不强行判Fail。
- [ ] 评测次数与总次数计算正确；建议次数不冒称标准。

## 最终交付
- [ ] 先回答用户要求的范围，附注不过度分散。
- [ ] 不因增加专项建议而擅自扩充用户指定用例数量。
- [ ] 任何可复用规则中，项目特定阈值都标记为实例配置而非通用默认值。
