# 零售合作模式分析

## 工作目标与边界

根据具体合作案例还原零售方、品牌方、平台方及其他参与者如何合作，归纳可复用的共性模式，为零售机器人或其他 B 端产品的定位与商业化提供依据。先遵循用户指定的对象、地域、时间窗口和工作阶段；只要求案例收集或某一图表时，不自动越过阶段交付完整方案。已给出案例或研究成果时先读取、核对并继承；不要把先前猜测当事实。

角色以案例实际承担的功能而不是名称判断。区分主体、产品和渠道；平台可能同时具备交易与流量、配送履约、零售技术服务、零售媒体能力，不强行互斥。区分平台与实际配送方、商家、服务商，以及消费者 App 和系统提供公司；标注已知关联关系。一方可兼任多种角色。自有品牌合作中零售商兼品牌经营方，另一方可能只是生产供应商。

## 1. 收集可核验案例

明确研究对象、目标、地域、时间范围及对标标准，以指定时间为界确定窗口。对需要现实案例、链接、近期信息的研究进行网络检索；优先企业官网、招采公告、上市公司披露、政府及行业协会，再补可靠新闻。确认来源直接支持每项关键信息并给出可访问链接，说明来源类型；不可用推断替代证据，不编造交易规模、价格、签约主体或权责。

默认案例表列为：零售方｜品牌方｜平台方｜第四方｜合作时间｜合作类型及具体分工｜信息源链接｜信息源类型。未参与或来源未披露以“—”占位，并说明“不代表实际不存在”；需要时细分未参与与未披露。时间注明签约、发布、上线、采购计划或既有合作的近期进展，不能把披露日期误称签约日；标明计划、试点、公告或实际落地状态。公开案例不足时说明边界。

## 2. 从案例归纳合作模式

逐例识别参与方、各自提供和需要的资源、活动顺序、可证实的规则与结算。横向比较共性和差异，归纳少量基本模式；将独家、首发、联合营销视为可叠加条款，将准入、品质审核、信誉背书视为机制或可能产生的价值，不强凑为独立模式。各基本模式可按合作目标、经营主体、商品或服务归属、谁履约、收入机制区分，并可回溯到案例。不要预设品牌或平台一定直接与商超签约。

针对品牌—平台：分析入驻与分销、数据洞察、站内营销、推广、即时履约、品牌代运营等实际合作，辨别平台提供的能力与由门店或第三方承担的工作。

针对零售—平台：分析平台入驻、引流交易、门店与库存协同、配送履约、技术系统、会员及零售媒体等实际合作，区分零售商自有渠道与平台渠道，辨别订单、拣货、配送、售后各由谁承担。

不要预先把以上清单当作事实或穷尽分类，按实际案例归纳。研究零售—品牌时可使用品牌供货＋零售销售、联合研发、自有品牌＋供应商生产作为起点，按证据修订。

## 3. 合作模式与业务流程表

默认一行一个基本模式，横轴严格按以下顺序：合作模式｜业务流程｜业务环节｜业务问题｜机会点｜盈利点。业务流程用箭头描述从合作启动到执行、复盘和结算的关键步骤；业务环节、问题、机会和盈利点用相同编号逐项对应，说明哪一方在何环节有何问题。不同环节可拆成多行以便阅读，但保持模式清晰。

机会点是可解决的问题与拟提供的能力；盈利点是拟向谁提供何种付费产品或服务及可探索的收费方式，而非营业额或利润结论。区分客户的降本/增收价值与产品服务商的收入，辨别受益方、使用方、采购决策方、签约方和付款方。机会、用户需求、收费方式、数据获取、真实成本、付费意愿均为待验证假设，不承诺盈利。若与零售企业或机器人产品规划相关，可讨论导购、试吃、补货理货、运营系统与数据服务等，但不得假定当前机器人已具备能力，也不将机器人强行对应到全部环节。若用户要求业务问题与产品能力对应，明确列出相关能力、实施条件、受益方及待验证事项；必要时给指标与合理对照。

## 4. 资源流与资金流图

默认分两张图，用精简文字和有向箭头表达实际关系。图中只放与场景有关的必要角色，按情境选择消费者、零售方、品牌方、平台方、供应商/生产商和第四方；不能为凑齐角色虚构合作。实际超过五个节点横向时使用自上而下布局或拆图。先理清箭头再画：

- 资源流：商品由提供方向接收方，服务由服务方向接受方，渠道、营销资源、数据信息和需求反馈分别按真正方向标注。零售方向消费者提供商品／购物服务；消费者向零售方提供需求／商品反馈。数据可否提供或共享视实际授权与协议，不假设无条件共享。
- 资金流：箭头从付款方指向收款方，具体标注商品款、采购款、代销结算、服务费、平台技术服务费、广告推广费或配送费等，按案例适用列出。买断、代销、自有品牌、平台结算分支可选，禁止将互斥模式画成同一笔交易或重复计费。明确销售货款、补贴、服务费和利润之间的区别；费用和结算主体未知时标为待验证，不根据利益直接推断付款方。
- 图中虚线表示按合作约定可能发生；附一句说明不同模式箭头不一定同时出现。不同主体之间存在双向流转时，分开画并标明各自内容，不使用无说明的双向箭头。

用户偏好的视觉：白色浅点阵背景、圆角浅色矩形节点、黑色细边框、简洁细彩色箭头、线旁短标签；资源流和资金流保持角色的相对位置与颜色一致。遵循用户提供的参考样式及交付格式；适合对话时可用 Mermaid，需分享或明确要求绘图时创建清晰的图片或可编辑图形。图中不引入没有证据的金额，绘制后核对箭头方向、标签、交叉遮挡、可读性及例外说明。

## 5. 结论与核验

给出关键未证实问题：协议及付款主体、费用及计价方式、合同期、库存/履约/退货责任、活动资源与补贴承担、数据权限和结算规则。必要时给零售、品牌、平台及服务商各自的访谈问题。明确区分来源直接披露、归纳推断及待验证假设；未经对照不能将销售增长全部归因于某项活动或机器人。

交付前核对：时间窗和来源可追溯；案例与抽象模式映射；表格列顺序及编号对齐；箭头方向正确且相互独立；预期收益和现实事实不混淆；内容简洁、只交付用户当前要求的阶段。
