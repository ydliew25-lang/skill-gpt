# 商品试吃数据评注

把每个判断写成一条可以复查的记录，使审核人能答出“哪位顾客、针对哪件商品、在哪个环节、具体表达或做了什么、依据在哪里”。以评注为默认交付。用户另有分析要求时，先完成评注，再使用有效标签汇总。

## 1. 锁定数据和规则

- 确认本次文件、版本、商品和会话范围。只处理用户指定的批次。对多个文件先核对是否同一份日志或同一拨互动的不同版本，分别保留批次键。保留名称、计价单位、容器、试样与正式零售品的对应关系。无法确认 SKU 时记录有证据的品名或品类。
- 采用用户本次指定的字典。无另行指定时使用随附的[项目正式字段与取值规则 V0.2](references/schema-v0.2.md)。先看所属类别，再核对具体字段的定义、枚举、适用场景、体验依据及缺失规则。仅使用字典已有代码；无合适值时用该字段允许的“其他”并保留原词，或记入待确认项。明确记录规则版本。
- 已有标注时沿用可定位的原文行号和有效标签 ID，从原材料查漏、从已有判断查错。用户指定模板时保留其结构。缺少可回查的原文时标出可核验范围。

## 2. 建原文表，完整读一拨

- 每个原始事件占一行。保留原文件行号、时间或片段位置、原编号、通道、说话人／动作主体和完整原文。同一原始行含多个时间戳事件时，依次增设事件 ID，同时保留原行号。系统配置、店员介绍、环境声、沉默取样也各有出处。
- 通读整拨再落标签。区分发言人、需求归属人、领取人、品尝人；同行者使用本拨局部编号。区分现场试样、同款零售品、替代品、以往买的他牌商品和试吃服务。说话人提到他人偏好时保留转述关系。
- 找出问题和答复、递送和接走、拒绝与原因、改口与最终选择。为含信息的片段标出主证据，支持判定的前后文列为旁证。只作背景的行保留原文，加处理说明。

## 3. 拆成最小判断，按字典取值

- 一个主体对一个对象、一个字段／细项的一次判断占一条标签。同一句涉及咨询、属性评价和购买计划时逐项建行，允许共用主证据。建议在标签表附“原声片段、正式维度名称、体验依据”等列便于筛选。
- 先辨语义，再选字段。顾客问什么看 E10；表达想要、接受或回避什么看 P；请求、取走、拒绝或改选看 E；描述某件商品的风味、包装、规格或总体喜好看 F；表达当次或未来购买计划看 F10。支付按 T03/T04 的外部记录确认。分别标注推荐目标是试吃还是购买。
- 写清具体细项。“字太小了”定位商品包装的文字字号；“一袋六个，一顿吃不完”定位商品包装规格的每袋件数。已有规格与个人感受可以确定，理想件数仍未知。F08 顾客明示的建议须有其提出的方案；品牌方自己想到的改法仅在需要时另列，注明来源。
- 感知、适宜度、态度分别取值。“这款不甜，正好”可同时支持 F03 强度 0 和 F05 正好。只描述味道时，保留描述；无态度证据时留空该子项。将“还行”放回所评对象，评价味道、外观或开口时填相应方面，评价整款时才考虑 F06。
- 在 Q01 分开写记录依据和表达方式。顾客原话、画面动作、系统回传与语境推定各有出处。零售去壳需求需单独识别；若只能从语境推定，另建一条并写明连接试吃与零售的具体证据。不要直接复用试样形态偏好作为零售取值。
- 逐子项处理证据不足。业务值留空并填 Q02 的具体原因；保留其余有证据的判断。例如有人明确想买，但镜头未拍清“这个”指什么，可保留购买意向，将商品对象列为待确认。需要时增设“对象值状态”等列；已记录的业务值可以为数值 0。

## 4. 按会话复核

检查多人口径、代拿、对象切换、否定、比较、改口、画外音和未完整观察的时间段。确认品尝按同一人、同一商品归属；拍到入口、本人自报或可归属的取样后咀嚼可作为证据。只看见取杯时记录取走与依据，品尝留空并说明。未确认入口时，仍保留有依据的包装、形态或感官反馈及其体验依据。

相同事实的重复解释合并证据；二次取样或不同颗粒的评价保留不同事件。顾客前后改口时用 Q04 关联原判断与后续判断，保留两段原声。对有分歧的细项记录“待确认”、判定理由和需补证据；已确认的细项继续交付。复用[逐条到逐项的示例](references/worked-example.md)核对粒度和主体归属。

## 5. 双向验收并交付

- **从原文找遗漏**。逐行检查每条有效信息有标签可回查；其余行有背景、重复旁证或不可辨等处理说明。
- **从标签查证据**。核对每条的主体、商品、细项、取值、主证据和规则版本。检查同一字段下的枚举与单位是否合法，拒尝原因是否由本人或上下文支持，补全判断理由。人工复核重点放在“问价→嫌贵”“接杯→品尝”“味道还行→整体喜欢”等容易多推一步的判断。
- 交付两张可筛选表。**逐条原文**覆盖整批原始记录；**标签明细**一行一个判断、包含主证据和旁证。待确认项可直接筛选 Q04 或附一张待核清单。在实际输出中将两张表的筛选范围延展至已填末行。若复核旧标，附原／新标签 ID 与更正原因。默认使用 Excel；用户指定其他格式时保持同等回查关系。
- Excel 模板和结构校验使用 [workbook.py](scripts/workbook.py)，依赖 Python 与 openpyxl。在技能目录运行下列命令；用新文件名生成模板。check 检查 ID、证据关联和基础值状态。业务取值、证据是否充分仍须人工逐项核对。使用同格式的新字段表时，可给 check 加 --schema 指定文件。该工具的质量状态枚举按 V0.2 校验；若这些枚举也有变化，另按用户指定的新规则核验。

```sh
python3 scripts/workbook.py init 试吃日志评注.xlsx
python3 scripts/workbook.py check 试吃日志评注.xlsx
```

报告覆盖了多少条原文、形成多少条有效标签、哪些子项待核及其原因。只有具备独立参考标注时才计算精确率或召回率。
