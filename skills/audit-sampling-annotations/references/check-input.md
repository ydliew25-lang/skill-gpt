# 结构检查输入与结果

使用 Python 3 运行 `python3 scripts/check_links.py INPUT.json`，或以 `-` 代替路径从标准输入读取。脚本只读输入，JSON 结果写至标准输出。退出码 0 表示本次检查没有报出结构问题，1 表示检出问题，2 表示输入无法读取或规范化结构有误。分母为 0 时结果为 `null`。

## 准备输入

以一个场次为一批。从 Markdown 原始日志独立提取原始记录为 `raw`。从 XLSX 等标注文件分别提取“逐条原文”为 `copied`、“标签明细”为 `labels`。记录两侧的文件版本、筛选范围、原始位置和表头映射。按原始行号或稳定事件键连接两侧；将标注文件里抄录的原文作为 `copied.text`，保留标点、空格和转义符。若模板只保存发言文本，双方使用相同的文本字段，在报告中注明覆盖范围。若没有原文抄录表，单列该检查为待评测，切勿从原始日志生成“已抄录”的替身。

以下为自编例子，其中一个字段取值为零。

```json
{
  "raw": [
    {"id":"L01","session":"场次配置","text":"今天试吃的为原味。","shared_with":["S01"]},
    {"id":"L03","session":"S01","text":"我觉得不甜。"}
  ],
  "copied": [
    {"id":"L01","session":"场次配置","text":"今天试吃的为原味。"},
    {"id":"L03","session":"S01","text":"我觉得不甜。"}
  ],
  "labels": [
    {"id":"F1","session":"S01","primary":"L03","support":["L01"],"status":"recorded","value":0},
    {"id":"F2","session":"S01","primary":"L03","status":"missing","value":null,"reason":"未提及"}
  ]
}
```

- `id`、`session`、`primary` 为非空字符串。原始证据ID在本批唯一。若行号按拨重置，把“源文件＋拨＋行号”拼成引用键，然后对三表使用同一映射。标签ID在标签明细内独立唯一。
- `raw.shared_with` 为可选的拨号列表，只用于原始资料中确实为多拨共享的记录，例如场次配置。显式列出允许引用的拨，省略时只可被同拨引用。同批顾客发言按本人所在拨处理。
- `support` 为可选的旁证ID数组，缺省等同空列表。来自不同文件的证据应带文件键，便于人工定位。
- 映射原表“已记录”为 `status: recorded`，业务值可为 `0` 或 `false`。映射字典承认的缺失状态为 `status: missing`，`reason` 保留原缺失类型，`value` 必须显式为 `null`。若原表缺少值列，省略该键以暴露结构缺项。保留无法识别的状态供纠错，禁止用已知状态替换。业务字典的枚举、单位和数值范围另行检查。

## 解释输出

| 指标 | 分子 | 分母 |
| --- | --- | --- |
| raw_rows_copied_exactly_once | 两侧各出现一次且文本、会话一致的原文行 | 原始行数，含重复行 |
| label_rows_with_resolvable_in_scope_evidence | 主证据及所列旁证均唯一定位、会话关系符合约定的标签行 | 输入标签行数 |
| label_rows_with_consistent_value_state | 取值、缺失状态和缺失原因符合本输入契约的标签行 | 输入标签行数 |

独立阅读 `issues`。例如多抄一行会出现在 `extra_copy`，即使原始行全部匹配。标签问题含标签ID和在规范化标签数组中的1起始行号。指标只覆盖提供的批次和以上结构，业务事件去重、Q02原因是否属实、证据能否支持标签、语义召回和最终验收均须另行核实。
