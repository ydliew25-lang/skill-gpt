# 原图构图可编辑PPT工作流

先明确内容与视觉依据，再把页面重建为可分别操作的对象。分别验收事实、原图构图和可编辑性；交付真实文件与可核对的预览。

## 入口与执行边界

1. 读取当前对话中的已确认要求和已有文件引用；保留用户对前一批的认可，不重新索要相同确认。
2. 使用当次可用的 **Presentations** 技能处理工具选择、原生构建、导出和基础验证。处理真实照片或图片编辑时使用对应技能；不将本技能绑定到固定库版本、旧工具名或旧工作目录。
3. 根据任务选择入口：新项目从需求与样页开始；已有认可原图直接建立原图索引并拆层重建；“继续第N—M页”仅制作该范围并保留全稿页码、风格和时长分配；整合总稿则读取各批实际文件、合并、补齐已要求的附录并整体验证。
4. 找不到旧文件时，先依据已知引用通过 Library 恢复；未解析目标按当前 Library 技能检索。无法恢复关键原图时，说明缺失页码并请求最少必要材料。先完成不依赖缺图的文字、备注和结构工作，不把重新想象的页面称为原图复原。
5. 用户只要求提纲、预览或指定批次时遵守本次范围。用户已授权全稿且未要求阶段审核时自主推进，不把每5页变成强制确认关卡。

## 1. 建立制作约定

记录主题、听众、用途、语言、页数、讲述时长、章节顺序、内容范围、来源要求、页面比例、输出格式，以及本次制作范围。缺少姓名、履历、单位徽章或个人照片时使用明确占位，不从个人记忆补写未经提供的讲师信息。

开工前确定两项：

- **排版优先级**：原图构图优先，或严格格式优先。记录用户明确选择的依据。超大标题与24—26磅上限可能冲突；依据最新明确要求执行。若仍无法判断，只问这一项关键选择，同时完成不依赖它的内容工作。不要暗中缩字或声称两种冲突标准都已满足。
- **可编辑范围**：逐类说明哪些对象必须原生，哪些允许独立图片层。需要编辑图标内部路径时，不把透明PNG当作矢量交付。

多批制作时使用 [production-state.md](references/production-state.md) 中的记录结构。页数和时长按项目设置；每批5页仅为未指定时的工作组织建议。

## 2. 准备内容、事实与讲稿

为每页确定一个中心问题或信息任务。把长解释移入演讲者备注，保留适量上屏文字。

依照 [sources-and-notes.md](references/sources-and-notes.md) 核对事实、政策适用年份、统计口径、照片学校/校区/场景与完整出处。未知适用届别或未来规则不作默认承诺。训练建议、虚拟案例与实证结论分别标识。

给每页添加核心信息、口头解释、下一页过渡、建议秒数、互动方式及耗时、完整来源。将互动与答疑包含在总时长内。附录是否计时、是否计入页数按用户要求记录。

## 3. 用代表性样页建立视觉规则

没有已确认风格时选择1—3页，覆盖主图/照片页和信息/流程页；用户指定样页时优先使用其页码。

从样页归纳网格、边距、标题/正文层级、颜色、背景层、照片边框、阴影、页码和来源位置。将变化项与固定项分开。用户没有选择特定风格时，不把冷蓝纸纹强加到所有项目；用户要求沿用本次学术纸纹风格时读取 [academic-blue-paper.md](references/academic-blue-paper.md)。

按用户要求提交样页审核；已有认可样页直接继承。最终需要可编辑PPT时，尽早用一页验证原生文字、图形与图片分层能否保留风格。用户只要求图片预览时交付预览，清楚记录尚未完成的PPTX部分。

## 4. 扩展视觉稿与素材清单

按章节或约5页一批推进。保持视觉规则，同时根据内容选择照片、表格、流程、对照或填写区，不机械复制同一布局。

给每页绑定已认可参考图、文字稿、备注、独立素材和来源编号。真实摄影保持原色、比例与水印。仅把获准的抽象材质作为生成图使用，不生成冒充真实校园、人物、实验室或成果的图片。找不到可靠素材时使用注明用途的占位。

需要透明底素材时单独整理图标或抠图，记录其仍为位图或已具备矢量路径。不要为凑齐素材把可直接用原生线条重建的流程再转为PNG。

## 5. 按原图分层重建

读取 [editability-and-qa.md](references/editability-and-qa.md)。逐页建立对象清单：背景底色、材质、背景字、标题/正文、照片、图注、图标、底板、线条/箭头、表格/图表。

- 文字使用真正的文字框；表格使用原生单元格；要求可改数据的图表保留原生图表与数据来源。
- 简洁图形、纸片、边框、箭头和填写线使用原生对象。照片、纸纹和允许的透明PNG作为独立图片。
- 保持认可原图的相对位置、主次比例、留白与叠放顺序；复用原始素材并尽量保留可恢复裁切。不用通用模板代替已确认构图。
- 给主要对象命名；组合用于便于操作，不将其扁平化。不靠整页截图、文字轮廓图或缩小字体冒充可编辑与合规。
- 明确写入字号、行距、字体和图片比例。1.5倍行距不是1.5磅固定行距；中文与英文/数字字体按项目约定分别设置。

需要并行时，让制作、来源/备注复核、视觉对照分别负责明确范围；避免同时修改同一份文件。

## 6. 分批验收与修复

每批执行四类验收：

1. **内容**：必需信息、年份、单位、案例性质、来源与讲师占位。
2. **视觉**：每页全尺寸对照原图；检查溢出、非预期换行、表格末行、照片比例、水印、标注和页脚。
3. **对象**：确认文字/形状/表格确为对应原生类型，图片层与参考一致；不能仅因存在一个文字框就判定全页可编辑。
4. **讲述**：备注完整，当前批次秒数与全稿计划匹配，互动和答疑不额外加时。

使用当前 Presentations 技能的正式验证流程。需要对象清单与补充检查时执行 `scripts/audit_pptx.py`，参数见 [editability-and-qa.md](references/editability-and-qa.md)。结构报告仅证明报告覆盖项目，不能证明视觉一致、字体安装或PowerPoint客户端运行效果。

导出实际PPTX后重新导入/渲染，再查看所有最终页面；修正受影响页并重导出。只有实际打开过PowerPoint才声称在该客户端检查过。字体缺失或未嵌入等影响使用的限制须如实说明。

## 7. 保存、交付与继续

按当次 Library 技能保存用户交付物，保持文件身份与版本；交付PPTX和必要的实际导出预览。用已验证链接，简要说明页码范围、可编辑范围和影响使用的限制，不附内部脚本或检查日志。

在制作记录中标明每批的内容、视觉、重建、导出验证和交付状态。用户继续下一批时复用记录，不重做已认可页面。

用户要求完整总稿时，合并已确认批次，统一页码和备注顺序，整理实际使用的来源附录，检查全稿讲述时长与放映顺序后交付。本次仅交付分批文件时，明确总稿和附录各自状态；不要把分批完成等同于已合并最终文件。
