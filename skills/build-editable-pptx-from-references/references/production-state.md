# 制作记录

在跨批次、跨会话或恢复文件时读取。维护一份简洁记录，格式可用JSON或表格；不用向用户展示全部内部记录。

| 字段 | 记录内容 |
|---|---|
| scope | 全稿正文页数、本次页码范围、附录是否包含、交付类型 |
| audience | 听众、用途、语言与背景知识 |
| timing | 全稿、章节与每页目标秒数；互动/答疑已包含 |
| priority | 原图构图或严格格式；用户明确选择的依据 |
| style | 比例、字体、字号层级、行距、色值、网格、页眉/页码规则 |
| editability | 必须原生的元素、允许的位图、已知能力限制 |
| references | 已认可样页/原图对应页码、稳定文件引用、可选哈希 |
| assets | 素材ID、内容/场景、原始来源、发布日期、文件引用、裁切与水印约束 |
| pages | 标题、必需文字、备注引用、素材ID、预期原生对象、验收状态 |
| deliverables | 已交付文件引用、页码、版本、实际预览、是否合并总稿 |
| unresolved | 影响交付的真实缺项与下一步，没有则留空 |

## 状态与授权

区分内容稿已准备、视觉稿已认可、原生对象已重建、导出已检查、文件已交付、全稿已合并、附录已完成。

“很好，继续第26—30页”通常表示沿用上一批认可方向，无需重新确认风格。保留全稿页码；文件内第1页可以显示26。

认可样页不代表未展示的事实自动获得确认。持续执行事实审核，只对会改变制作目标的未决冲突提问。

## 恢复与版本

保存稳定文件引用，工作目录仅作当前路径。临时文件丢失时先从持久文件恢复，不把缺失当成用户删除。不将私人目录、旧会话路径或过期下载链接写入可复用技能。

区分原始参考与交付版本。修订已有文件时遵循对应存储技能的身份和版本规则；未经要求不改前一批。

## 时间与整合

全稿时间包含正文、所有互动和答疑；按用户要求排除附录。核对每页秒数及章节合计，不因独立导出一批而重新分配全稿时间。

完整总稿交付前检查缺页、重复页、错序、未授权过渡页，以及合并后的备注和全稿页码。
