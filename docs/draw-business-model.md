# 绘制商业模式图

将已有商业分析转为参与方、资源与服务、资金、机会点和潜在收费清楚对应的关系图。适合合作方案、商业模式讨论、产品规划和业务汇报。

[查看 Skill 主规范](../skills/draw-business-model/SKILL.md) · [返回仓库首页](../README.md)

## 适合什么任务

- 根据合作分析或案例表，梳理零售方、品牌方、平台及实际涉及的第四方之间的关系。
- 在一张连续网络中呈现资源/服务流与资金流，并标注适用条件。
- 将商业机会与相应潜在收费放到具体关系上，明确谁受益、谁使用、谁付款、谁收款。
- 在保留已确认业务内容的前提下，改善既有图的节点位置、线道、箭头和文字可读性。

任务范围由用户材料与要求决定。单纯出图不自动扩展为完整调研；缺少关键证据时保留待确认项。

## 输入与输出

| 项目 | 需要准备或交付的内容 |
|---|---|
| 业务材料 | 合作分析、案例表、已有关系清单或参考图 |
| 范围 | 本次涉及的参与方、合作模式、需保留的内容 |
| 展示要求 | 受众、用途、配色、画布或交付格式；有明确要求时优先遵循 |
| 中间检查依据 | 发出方、接收方、流动内容、合作形式、机会/潜在收费、适用条件与证据 |
| 默认交付 | 高清 PNG 与可编辑 SVG；用户指定其他格式时以其要求为准 |
| 结果说明 | 待验证事项，以及仍未解决的覆盖或布局限制 |

关系清单用于组织和核验绘图内容，不意味着每次都额外交付一张表；按用户当前阶段的要求交付。

## 七步工作流

1. 确定受众、用途、范围、来源与交付格式。
2. 建立关系清单，区分角色与经营主体。
3. 判断每条资源、服务和资金的方向，拆开双向关系。
4. 将机会与潜在收费对应到具体关系，并保留验证边界。
5. 设计节点位置、连接端口和独立线道。
6. 使用可控矢量或代码绘图，生成所需文件。
7. 对照关系清单逐边核验，并渲染检查实际阅读效果。

## 核心图形规则

| 规则 | 默认要求 |
|---|---|
| 方向 | 资源/服务从提供方指向接收方；资金从付款方指向收款方 |
| 同一对主体 | 双向关系分别画箭头；资源与资金分别画线 |
| 线条颜色 | 跟随箭头发出方的模块颜色 |
| 线型 | 实线表示资源/服务；虚线表示资金；“依约”等条件用文字表达 |
| 机会点 | 将机会名称本身设为黑色加粗 |
| 潜在收费 | 将对应收费项目名称本身设为红色加粗，并区分付款与收款主体 |
| 整体网络 | 用户要求单张图时保持连续网络，参与方原则上各出现一次 |
| 布局 | 优先调整节点、画布和线道，消除交叉、重合与遮挡；文字和箭头对应唯一 |
| 事实边界 | 机会、付费意愿及盈利能力未经证实则保留为待验证；收入不直接等同利润 |

用户明确的新要求优先。复杂拓扑或内容密度可能使“全部关系、单张图、零交叉、足够字号”等要求无法同时满足，需要说明冲突并按用户优先级取舍，不能承诺任意图均可实现零交叉。

## 调用示例

> 请使用“绘制商业模式图”Skill，根据我提供的合作分析绘制一张资源流与资金流合并图。保留全部已确认的参与方和关系，参与方原则上各出现一次；线条颜色跟随发出方，资源/服务用实线、资金用虚线。将机会名称本身设为黑色加粗，将对应收费名称本身设为红色加粗。重新安排节点和线道，让每段文字明确对应一条箭头。输出高清 PNG 与可编辑 SVG，并说明待验证事项和未解决的布局限制。

在支持按技能名调用的环境中，可使用 `draw-business-model`。具体导入方式与触发语法由运行环境决定。

以上是使用示例，不是已生成的业务图或案例结论。

## 文件与运行依赖

| Skill 内文件 | 用途 |
|---|---|
| `SKILL.md` | 主工作流、默认绘图规范与出图核对要求 |
| `agents/openai.yaml` | 显示名称、默认提示与图标路径 |
| `assets/icon.svg` | Skill 显示图标 |

这 3 个文件完整保留既有 Skill 的原始内容；没有附带独立绘图脚本、参考图库或成品示例图。

执行时需要能够读取用户材料、生成可控矢量图、渲染中文、预览图像及导出文件的 AI 环境。具体工具由宿主提供；本仓库不指定某一个绘图库，也不据此宣称跨平台运行已经验证。

## 公开内容与检查范围

本目录收录通用工作流，不包含实际合作合同、内部报价、私人对话或业务数据库。规范中的“试吃”“试吃服务费”等仅用于说明标注方式。

此次整理检查了文件完整性、配置语法、相对路径和导出副本一致性。绘图规范要求执行时检查业务逻辑和视觉效果，实际生成的每张图仍须按该要求复核。
